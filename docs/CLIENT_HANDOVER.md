# Cottonil Client Handover — Engineering Package

Date: 2026-10-29. **Engineering handover candidate, NOT production acceptance.**

## Included
- FastAPI backend, React/TypeScript frontend source, authenticated APIs, business intelligence tools, bilingual deterministic Copilot and optional (unverified) LLM adapter.
- Persistent auth session/audit schema, role-based and branch-limited access, investigation rule trace ledger, source hashes, executive PDF/Excel code and governed decision workflows.
- Docker/Compose blueprint, Windows startup, database backup/restore, GitHub Actions QA, Python tests, Playwright smoke source and release documentation.
- Private customer data, credentials, model checkpoints, populated databases, virtual environments and npm packages are deliberately **excluded**.

## Verified here
- 86 original backend tests passed before modification; 98 final backend tests passed after modification.
- Synthetic test data validates branch separation, session security, audit, backup/restore and absence of unsupported investigation cases.
- **Frontend build, live UI, deployed services and live company data were not verified.**

## What Cottonil must provide/approve
- Approved, current CSV extracts and a signed source schema/data dictionary with owner for each KPI.
- Branch-to-user mapping, administrator accounts, external domain/TLS/certificate and secret custody.
- Data-use consent, retention policy, formal vulnerability/pen-test clearance, staging access and accountable operational support owner.
- Validation of sourcing unit equivalence, branch opening dates, marketing attribution, order reconciliation and business definitions; sign-off on trust classification.

## Suggested acceptance demonstration
1. Show login/logout, role denial, branch isolation and audit of export on secured staging.
2. Demonstrate start without data and explicit user-facing missing-data status.
3. Ingest approved client inputs in staging, inspect source hashes and use `/api/reconciliation/status` to validate NEX case triggers.
4. Compare front-end English/Arabic views, responsive layout, downloads and navigation against actual API evidence.
5. Test real backup/restore, documented outage and rollback, and recovery after configuration updates.
6. Run CI/security audits and record all evidence before a signed production go/no-go decision.

## Release verdict
**NO-GO for public/production use pending final acceptance.** Current deliverable is a source-based integration and security milestone with passing backend tests. See QA and security reports for exact unverified surfaces.
