# V13 security-hardening checkpoint — NOT production certified

## Verified in this environment
- `PYTHONPATH=backend pytest -q backend/tests` — **51 passed** (28 October 2026).
- Production config validation rejects disabled authentication, short auth secret, non-hashed users, missing admin account, short write token, non-HTTPS CORS origin, and out-of-policy token lifetime.
- Production rejects authentication via query-string `access_token`. Bearer Authorization header is required.
- Authenticated viewer is denied all non-login POST/PATCH/PUT/DELETE endpoints by middleware. Existing write-token controls remain in place.
- API adds no-store, nosniff, no-referrer, frame-deny, and production HSTS response headers.

## Still blocking an actual production launch
- Frontend `npm ci` timed out here; build and browser E2E NOT VERIFIED.
- Database uses SQLite; no demonstrated concurrent multi-user load, managed backups, recovery test or data migration strategy.
- Authentication uses static environment configured accounts and process-local tokens, with no centralized lockout, MFA, session revocation, rotation, or tested distributed rate limiting.
- No demonstrated reverse proxy TLS deployment, secrets manager, external security audit, vulnerability scanning, compliance approval, or deployment pipeline.
- Branch-level authorization and tenant isolation are not implemented. This is a major security blocker for multi-branch access.
- ML baseline and deterministic Copilot are not equivalent to validated advanced models, continuously retrained models, or independently evaluated production agents.
- Historical metrics have outstanding reconciliation warnings; do not treat uncertain KPIs as certified.
- PDF Arabic rendering needs visual validation.

## Production configuration (never commit real secrets)
Set `NEXUS_ENV=production`, `NEXUS_AUTH_ENABLED=1`, a unique randomly generated `NEXUS_AUTH_SECRET` (>=48 characters), `NEXUS_WRITE_TOKEN` (>=32 characters), `NEXUS_USERS` with PBKDF2 hashes generated by `scripts/make_user_hash.py`, `NEXUS_CORS=https://your-real-frontend-domain`, and `NEXUS_AUTH_TTL_MIN=30`. Serve the API over HTTPS behind a properly configured reverse proxy. Tokens must be supplied in the Authorization header. Development-only plaintext passwords must not be used.
